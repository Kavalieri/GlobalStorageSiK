# Global Storage SiK 1.5.7

This release incorporates the first measured implementation pass prompted by
[Issue #1](https://github.com/Kavalieri/GlobalStorageSiK/issues/1).
Thanks to iceriny for the detailed diagnosis. The issue remains open.

## Improvements

- Server-owned deposit/withdrawal tasks retain fixed selections, cursors and receipts,
  revalidate access/capacity and report compact progress.
- Both queues share a two-slice/5 ms budget per tick and alternate the first turn.
  Each task type is limited to 128 tasks globally and four per player.
- Snapshot publication and source-topology lookup are coalesced around each slice.
  Compatible inventory-container runs in physical gestures are batched.
- Bounded node journals choose smaller deltas where possible, falling back to full
  nodes when the base is incompatible.
- Selective fragment recovery, late ACK handling, idempotency and partial catalog
  resume avoid unnecessary full replay and redundant work.

## Fixes

- Terminal installation across floors no longer inherits the previous terminal
  session; server-side installation validation remains authoritative.
- Garlic, onions and edible crops use Produce; actual seeds retain Farming.
- Technical compatibility reviewed against PZ 42.21. Minimum build remains 42.20.
  Use SiK UI Framework 1.0.6 for the opacity-tooltip formatting correction.

## Issue #1 coverage

| Proposal | Status in 1.5.7 | Evidence and limits |
|---|---|---|
| Snapshot/topology per slice | Implemented | Deterministic fixtures reduce 10/100/1,000 captures to 1/10/100. |
| Server-owned task/cursor | Implemented | A 1,100-ID fixture advances 110 slices in 55 ticks with two checkpoints. |
| Shared work budget/fairness | Implemented for transfer slices | Not an independent global outbound-byte budget. |
| Physical batching | Partial | Container runs are batched; floor objects retain individual locators and conservative execution. |
| Node deltas | Implemented with fallback | A 41-node fixture compares a 408,486-byte full representation with a 9,488-byte delta. |
| Immutable versions retained for a whole catalog round | Partial | Bounded journals/recovery exist; a completely pinned round under a shared retained-version budget is not provided. |
| Two to four node blocks in flight | Deferred | Blocks remain sequential; four ACKs enabling partial display do not mean four concurrent blocks. |
| Separate outbound-byte budget | Deferred | Needs traffic, decode and concurrency measurements. |
| Confirmed row refresh every 100–200 ms | Deferred | The managed-transfer list is still deferred until completion/cancellation. |
| Selective retry/partial resume | Implemented | Development contracts pass; dedicated measurements after the correction remain pending. |

No evidence establishes that deferred proposals were rejected because their
measured gain was too small. They remain open because measurements and regression
evidence are incomplete. Additional in-flight blocks could increase payload/decode
peaks; that is a risk to measure, not a demonstrated result.

All figures above are deterministic development-fixture results, not PZ runtime
timings or real-network bandwidth measurements. Continue testing 1/2/4 observers,
cold/warm catalogs, 10/100/1,000-unit operations, p50/p95, bytes/messages,
cancellation, disconnection, missing/late ACKs and journal fallback.

Annana's crop-category report is addressed. Custom item-type input and rotten-food
routing still need exact inputs and directed reproduction. The floor-placement
transport-policy failure was reproduced in a harness; the original player's full
runtime scenario has not been claimed as reproduced.

## Resumen en español

### Mejoras
Tareas autoritativas con cursores, presupuestos compartidos, batching físico,
deltas por nodo y recuperación selectiva con ACK tardío, idempotencia y reanudación.

### Correcciones
Terminal entre plantas; ajo, cebolla y cosechas comestibles en Frutas y verduras,
con semillas reales en Agricultura. Compatibilidad técnica revisada con 42.21.

### Pendiente conocido
La optimización continúa. No se incluyen ventana de 2–4 bloques, presupuesto
independiente de bytes ni refresco de filas cada 100–200 ms. No hay una medición
que justifique atribuir su aplazamiento a una reducción insuficiente.
La Issue #1 permanece abierta.
