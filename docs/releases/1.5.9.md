# Core 1.5.9 / Tablet 1.5.3 — Project Zomboid 42.22.2

## Español

### Core 1.5.9 — Correcciones

- Una red llena ya no impide registrar contenedores en otra red con plazas
  disponibles. El cupo configurado se aplica por red. Se mantienen el valor
  predeterminado de 128 y la protección global de 8192 para nuevas altas.
- Los resultados de reescaneo distinguen límite de zona, red y registro global.

### Tablet 1.5.3 — Correcciones

- Corregido el host del selector de redes que podía provocar
  `attempted index: width of non-table: null` al abrirlo.

### Validación y límites

El arreglo funcional se validó en una copia de una partida existente con
cliente y servidor dedicado PZ 42.22.2, usando Framework 1.0.6 publicado.
Se observó el registro real de dos contenedores con el cupo configurado en 128.
El usuario dio su visto bueno general sin observar errores adicionales.

El control publicado reprodujo el bloqueo entre redes. El candidato superó
nueve casos de frontera en Kahlua de PZ, con las dependencias de mundo simuladas:
red ajena con 128, última plaza, aceptación de 128 y rechazo de 129, destino
lleno, actualización de un registro existente, adopción con plaza, adopción
rechazada en destino lleno, protección global 8192/8193 y liberación por exclusión.
Estas pruebas aisladas no llenaron físicamente la partida con 128 o 8192 cajas.

La promoción conserva esos tres archivos funcionales. El delta posterior es de
versiones, identidad y documentación. No se atribuye una nueva prueba en juego
a esos bytes de promoción. Esta ronda no acredita singleplayer, una partida
nueva ni cobertura universal de otros mods o mapas. Las incidencias externas
registradas al arrancar no se presentan como resueltas.

La causa del informe `UnknownFormatConversionException` sigue abierta. Su
ausencia en el registro revisado no demuestra la resolución de todas sus causas.
Framework y los demás addons mantienen sus versiones. La evaluación de escaleras
y palancas es independiente de esta actualización.

## English

### Core 1.5.9 — Fixes

- A full network no longer prevents container registration in another network
  with available slots. The configured quota applies per network. The default
  remains 128 and the global new-admission guard remains 8192.
- Rescan results distinguish zone, network and global registry limits.

### Tablet 1.5.3 — Fixes

- Fixed the network selector host that could cause
  `attempted index: width of non-table: null` when opening it.

### Validation and limitations

The functional fix was validated on a copy of an existing save with a PZ 42.22.2
dedicated server/client pair and published Framework 1.0.6. Two containers were
registered in the actual game with the quota configured at 128. The user gave
general approval without observing additional errors.

The published control reproduced cross-network blocking. The candidate passed
nine boundary cases in PZ Kahlua with simulated world dependencies: another
network with 128, last slot, accepting 128 and rejecting 129, full destination,
updating an existing entry, adoption with room, rejection of adoption into a full
destination, the global 8192/8193 guard and freeing a slot by exclusion. These
isolated tests did not physically fill the save with 128 or 8192 crates.

The promotion preserves the three functional files. Later changes concern
versions, identity and documentation. No additional in-game test is attributed
to those promotion bytes. This round does not establish singleplayer, fresh-save
or universal compatibility with other mods or maps. Recorded external startup
issues are not claimed as resolved.

The cause of the reported `UnknownFormatConversionException` remains open. Its
absence from the reviewed log does not prove that every cause has been fixed.
Framework and other addons retain their versions. Ladder and crowbar assessment
is independent of this update.
